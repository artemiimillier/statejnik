# Чек-лист соответствия (compliance)

> **Когда читать:** перед публикацией любого продающего материала и сразу после публикации (Этап 14 - аудит соответствия на проде). Это последняя дверь перед тем, как страницу увидит широкая аудитория.
>
> **Зачем:** убедиться, что текст не нарушает ваш стоп-словарь и не создаёт юридического риска. Юр-риск реален: текст уже на проде, перед аудиторией, и цена ошибки растёт со временем.
>
> **Главный принцип:** это **полностью конфиг-зависимый этап**. Что именно нельзя говорить - задаёте вы в `editorial.banned_words`. Методология даёт механику проверки, словарь - ваш. Право конкретной юрисдикции (какие именно законы, штрафы, прецеденты, лицензии) - вне этого файла: он переносим. Здесь - универсальные принципы, которые держат большинство регуляторов по рекламе и защите прав потребителей. **Если в `statejnik.yaml` задано `legal.region: "ru"` - дополнительно и обязательно прогоняется модуль `references/checklists/legal-ru.md`** (образовательная лексика ФЗ-273, гарантии результата УК-159, англицизмы в рекламе ФЗ-53, персональные данные 152-ФЗ, маркировка рекламы 38-ФЗ/ЕРИР, возвраты ЗПП, чеки 54-ФЗ).
>
> ⚠️ **Проверять надо рендеренный HTML с прода, а не черновик.** Между черновиком и продом проходит рендер, в котором всплывают тексты, которых не было в исходнике: микроразметка, хлебные крошки, sidebar, авто-вставленные CTA-блоки, шаблоны «похожие статьи», карточка автора. Стоп-слово может прилететь из любого слоя.

```bash
# Скачать рендеренный HTML с прода и держать его входом для всех проверок ниже:
SLUG="<slug-статьи>"
curl -s "https://<config.project.domain><config.project.content_path>/$SLUG" > work/$SLUG/compliance-prod.html
```

---

## 1. Стоп-слова и табу ниши (`editorial.banned_words`)

Главная и самая нишевая проверка. Прогони греп по каждому корню и фразе из `editorial.banned_words` на рендеренном HTML. Каждое попадание выпиши с номером строки, контекстом и предложенной заменой.

```bash
# Собери регэксп из editorial.banned_words (корни/фразы через |):
grep -nEi "<корень-1>|<корень-2>|<фраза-3>" work/$SLUG/compliance-prod.html
```

В `editorial.banned_words` держите три класса запретов:

1. **Бренд-табу** - как НЕ называть свой продукт, ошибочные написания бренда, нежелательные позиционирующие формулировки.
2. **Лицензируемые термины ниши** - слова, которые по закону вправе использовать только обладатель лицензии/сертификата/разрешения. Употребление такого термина без основания - прямой повод для претензии профильного регулятора. Если у вас нет соответствующего разрешения, а в нише есть такие термины (и их «бытовые» синонимы, которыми принято прикрываться) - в стоп-словарь, и проверять отдельно.
3. **Англицизмы с готовым русским аналогом** - если ваша ниша/юрисдикция требует чистого языка (особенно в рекламе).

**Особые случаи (не нарушение):**
- Слово из стоп-словаря, **процитированное как пример самого правила** (самоописание) - помечай отдельно.
- **Имя собственное** (название стороннего продукта/компании может легально содержать корень из вашего списка) - исключение.

**Замена** - на разрешённый синоним. Если для запрещённого термина в нише есть «безопасная» формулировка - держите пары «не говорим / говорим» рядом с `editorial.banned_words`.

## 2. Обещания гарантированного результата (главный юр-риск маркетинга)

Это **переносимая категория**, не привязанная к конкретной стране. В большинстве юрисдикций обещание гарантированного результата в материале, который продаёт, - повод для претензии регулятора по рекламе или защите прав потребителей, а в тяжёлых случаях для иска.

```bash
grep -nEi "гарантиру[еюя]|100%\s*результат|стопроцентн|обязательно\s+(получите|заработаете)|гарантированно|обещаем\s+(результат|заработок)|гаранти[яю]\s+трудоустройства|после\s+(программы|курса)\s+будете" work/$SLUG/compliance-prod.html
```

Любое попадание = 🔴 STOP. Переписать на проверяемую формулировку:

| Палево | Безопасная замена |
|---|---|
| «Гарантируем заработок X» | «Передаём методологию / подход» |
| «100% результат» | (удалить, не использовать) |
| «Гарантируем трудоустройство» | (удалить) |
| «Обязательно построите Y» | «Показываем, как другие построили Y» |
| «После программы будете работать как Z» | «Сможете применять подход Z» |

**Гарантировать можно только возврат денег** - и только если это реально прописано в вашей оферте.

---

## 3. Ложная срочность и проверяемая ложь

Искусственный дефицит и поддельные дедлайны - вторая по частоте претензия по рекламному праву в большинстве юрисдикций.

```bash
grep -nEi "осталось\s+[0-9]+\s+мест|успей|только\s+сегодня|до\s+полуночи|последний\s+шанс|цена\s+вырастет\s+через" work/$SLUG/compliance-prod.html
```

Туда же - любое конкретное проверяемое утверждение, которое неверно: «открытый репозиторий», когда он закрытый; «работает у сотни клиентов», когда меньше; выдуманные цифры. 🔴 STOP - это и репутация, и в рекламном контексте юр-риск. Замени выдумку на факт.

> Все эти обороты держи в `editorial.banned_words` - тогда их ловит и стоп-словарь на Этапе 8, и греп здесь.

## 4. Микроразметка не противоречит табу ниши

Если адаптер площадки (publish.py) генерит structured data - убедись, что в ней нет типов и полей, запрещённых твоим стоп-словарём для твоей ниши. Если в нише есть **лицензируемые форматы** - соответствующие типы разметки тоже под запретом. Должны остаться только нейтральные типы.

Проверять именно на проде: разметка собирается из боевых данных и может отличаться от черновика. Нет ограничений в `editorial.banned_words` - закрой как `[x] SKIP`.

## 5. Персональные данные

Не свети чужие персональные данные. Греп на контакты живых людей в рендеренном HTML:

```bash
grep -nEi "[a-z0-9._+-]+@[a-z0-9.-]+\.[a-z]{2,}" work/$SLUG/compliance-prod.html   # email
grep -nE  "\+?[0-9][[:space:]-]?\(?[0-9]{3}\)?" work/$SLUG/compliance-prod.html       # телефоны
```

В тексте допустимы только **служебные** адреса (ваша поддержка, юрконтакт). Email и телефоны клиентов = 🔴 STOP.

- Если статья показывает данные реальных людей (отзыв, кейс с именем, лицо на фото) - flag «подтвердить согласие». Без подписанного согласия - убрать или обезличить.
- Если на странице есть форма сбора контактов - рядом должна быть ссылка на политику конфиденциальности и явное согласие.
- Если упоминается запись (эфира, звонка, встречи) - должен быть упомянут факт записи и согласие участников; хранение - по правилам вашей юрисдикции.

⚠️ Правило «не свети ПДн» относится и к рабочему чату/выводу агента, не только к публикации: не выводи email/имена/телефоны/идентификаторы людей без явной необходимости.

## 6. Внутренности бизнеса (self-disclosure)

Отдельная проверка, которую не покрывает ни стоп-словарь, ни PII-греп: не вытащил ли текст наружу то, что должно остаться внутри компании. Это блокирующая категория (Agent 7 в Этапе 7 методологии).

- [ ] Нет внутренних цифр бизнеса (выручка, конверсии, размер базы, число участников) - кроме официально опубликованных, с источником
- [ ] Нет имён сотрудников и подрядчиков вне согласованных публичных ролей
- [ ] Нет фраз из внутренних обсуждений и переписок («мы решили», «в чате договорились»)
- [ ] Нет деталей инфраструктуры: пути, серверы, имена внутренних систем, любые хвосты секретов/токенов (🔴 немедленно)
- [ ] Нет «проверяемой лжи» о компании («у нас 1000 клиентов», «мы первые») без публичного источника
- [ ] Личный опыт владельца - только из согласованного архива (`voice.source`); работа агента не выдана за «я проверил» от имени человека

---

## 7. Реквизиты и обязательные блоки

Не привязано к конкретной стране, но держи в этом gate:

- [ ] **Реквизиты издателя** в подвале/контактах (юридическое лицо + регистрационные номера по правилам вашей юрисдикции).
- [ ] **Условия возврата**, если упоминаются, - соответствуют вашей оферте. Нет формулировки «деньги не возвращаются», если она нарушает права потребителя в вашей юрисдикции.
- [ ] **Адрес для претензий** = ваш юридический адрес.
- [ ] Если материал **рекламный** (платное размещение, реклама у партнёров) - соблюдена маркировка рекламы по правилам вашей юрисдикции (указание рекламодателя, обязательные пометки, регистрация креатива, если требуется).

## 7. Полный pre-publish gate

Перед тем как оставить страницу опубликованной - все пункты:

### Стоп-словарь
- [ ] Греп по `editorial.banned_words` пройден (0 попаданий или явно подтверждено как самоописание/имя собственное)
- [ ] Лицензируемые термины ниши не использованы без основания
- [ ] Англицизмы с русским аналогом убраны (если ниша/юрисдикция требует), с учётом исключений и имён собственных

### Гарантии и срочность
- [ ] Греп `гарантиру[еюя]|100% результат|обязательно получите|стопроцентн` - 0 попаданий
- [ ] Нет «гарантии трудоустройства», «обязательно построите», обещаний дохода
- [ ] Нет ложной срочности («осталось N мест», «успей до полуночи», «цена вырастет»), если это неправда
- [ ] Цифры и кейсы - реальные, с источниками или с пометкой «личный опыт»

### Микроразметка
- [ ] Нет запрещённых/лицензируемых типов из `editorial.banned_words` (или SKIP, если CMS не генерит)

### Персональные данные
- [ ] Email/телефоны клиентов не показаны без согласия
- [ ] Если форма сбора данных - ссылка на политику конфиденциальности рядом
- [ ] Если показаны данные людей (отзыв, фото, кейс) - есть согласие
- [ ] Если упоминается запись - факт записи и согласие отражены

### Реквизиты
- [ ] Реквизиты издателя в подвале/контактах
- [ ] Условия возврата (если упоминаются) - корректны, без запрещённых формулировок
- [ ] Если материал рекламный - маркировка по правилам юрисдикции

---

## Финальный gate

Все пункты выше. Если хоть один fail - **НЕ оставляй страницу опубликованной**. Порядок:

1. Если 🔴 критично (гарантии, ложь, ПДн, лицензируемый термин) - поднять владельцу.
2. Править из `work/site.json` (site.py scan) и `work/published.json`.
3. Дождаться переиндексации (revalidate/rebuild у вашего CMS).
4. Повторить аудит с начала на рендеренном HTML с прода.

**Реальный случай из эксплуатации.** При системном аудите однажды нашлось несколько десятков накопившихся нарушений в полутора десятках уже опубликованных материалов. Контент уходил на прод и потом долго правился - цена ошибки росла со временем. Вывод: аудит соответствия на проде - не формальность, а последняя дверь перед публикацией для широкой аудитории. Лучше один раз пройти gate, чем месяцами вычищать выдачу.
