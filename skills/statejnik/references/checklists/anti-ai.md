# Чек-лист anti-AI - как не палить машинный текст

> **Когда читать:** перед публикацией любой статьи. Это канонический источник всех антипаттернов и автозамен для Этапа 8 (цикл хуманизации). Открыть и держать рядом до начала правок.
>
> **Зачем:** единый словарь всех маркеров, которые выдают, что текст писала языковая модель, а не живой человек. Грубо: «если эта фраза прошла - текст уже не звучит как человек». Поисковые антиспам-классификаторы давно научились ловить формальные маркеры шаблонного машинного текста (типографские символы, скрытые байты, клише в фиксированных позициях, монотонную длину предложений), поэтому чистим до нуля.
>
> **Откуда берутся словари табу:** все нишевые/бренд-стоп-слова - из `editorial.banned_words`. Все «звучит не по-вашему» фразы - из `voice.forbidden`. Имена собственные (продукты, каналы, бренды) из `voice.forbidden`/`config.*` исключаются из любых автозамен.
>
> **Главный принцип:** этот файл - единая точка истины для проверки хуманизации. Агент перед публикацией пробегается по разделам 1-16 сверху вниз и проверяет каждый паттерн. Если всплыл новый антипаттерн, которого тут нет, - дописать его сюда (Rule → Why → How) и опционально добавить правило в `scripts/ai-cadence-check.py`, чтобы следующая статья ловила его автоматически.

## 1. Пунктуация - обязательные автозамены

| Антипаттерн | Замена | Grep-команда |
|---|---|---|
| Длинное тире `—` (U+2014) | Дефис `-` | `grep -c '—' <path>` (должно быть **0**) |
| Короткое тире `–` (U+2013) | Дефис `-` | `grep -c '–' <path>` |
| Многоточие одним символом `…` (U+2026) | Три точки `...` или (чаще) запятая | `grep -c '…' <path>` |
| Типографские кавычки `"` `"` (U+201C/201D) в технотексте | Прямые `"` или ёлочки `«»` по вашей типографике | `grep -nP '[\x{201C}\x{201D}]' <path>` |
| Типографские апострофы `'` `'` (U+2018/2019) | Прямой `'` | `grep -nP '[\x{2018}\x{2019}]' <path>` |
| Zero-width space (U+200B), ZWNJ/ZWJ/BOM (U+200C/200D/FEFF) | Удалить - нормальному тексту не нужны **никогда** | `grep -nP '[\x{200B}\x{200C}\x{200D}\x{FEFF}]' <path>` |
| Non-breaking space (U+00A0) | Обычный пробел | `grep -nP '\x{00A0}' <path>` |
| Лишнее экранирование разметки (`\.`, `\-`, `\!`, `\*`) там, где оно вылезет видимым символом | Удалить | `grep -nE '\\[.!\-*]' <path>` |

**Безопасная автозамена (детерминирована, контекст не нужен):**

```bash
sed -i '' 's/—/-/g; s/–/-/g; s/…/.../g' <path>
```

⚠️ **Source check.** Типографский символ может рендериться из шаблона CMS (карточка цитаты, hero, футер, авто-CTA), а не из самого текста статьи. Если чекер на черновике чист, а аудит финального HTML с прода (Этап 15, Слой A) валит провал - искать в шаблонах компонентов вашего движка, а не в тексте. Прецедент из эксплуатации: фигатура-подпись автора цитаты содержала длинное тире в шаблоне (`<span>— автор</span>`), и каждая цитата протаскивала em dash в финальный HTML. Команда поиска по шаблонам: грануляция зависит от стека, но искать `—` нужно во всех слоях рендера, не только в `work/<slug>/draft.md`.

## 2. Симметрии «не А, а Б»

**Что палит:** повтор шаблона «не А, а Б» 2+ раза в одном тексте. Любимая риторика копирайтерских машинных гайдов.

**Правило:** **допустимо 1 раз** за весь текст (для драматического эффекта). Если регекс ниже находит >1 совпадения - переписать.

```bash
grep -nP ' не [^.,;:!?]{1,40}, а [^.,;:!?]{1,40}' <path> | wc -l
```

⚠️ **Этот греп регистрозависим и пропускает начало предложения.** Он требует пробел перед строчным «не», поэтому «**Не** должность, а дело» в начале клаузы или после жирного маркера `**` для него не существует. Прецедент из эксплуатации: первый греп показал ноль, семантический агент нашёл два таких разворота, оба с заглавной. Второй греп обязателен:

```bash
grep -nP '(^|[.!?»)]\s+|\*\*\s?)[Нн]е [^.,;:!?]{1,45}, а [^.,;:!?]{1,45}' <path>
```

### 2.0. Прогонять канонический греп дословно - свой вариант прячет нарушения

**Прецедент из эксплуатации.** Агент сочинил «более точный» регекс, требующий «не» сразу после границы предложения. Тот вернул 1 совпадение при лимите 1 - зелёный результат. Канонический греп на том же файле нашёл **8**. Пропущенное выглядело так (слово «не» в середине предложения): «Считать надо **не** по тарифам, **а** по своему расходу».

**Правило: команды из этого файла копировать дословно.** Улучшение регекса - отдельная задача с правкой чек-листа, а не самодеятельность в момент проверки. Где вариантов несколько - прогонять **все** и объединять по позиции совпадения, чтобы не считать одно нарушение дважды. Греп прогоняется **после каждой итерации правок**, а не один раз перед публикацией.

### 2.0a. Инверсия «Y, а не X» - грепы выше её НЕ ловят

Тот же разворот в обратном порядке: сначала утверждение, потом отрицание через «а не». Регекс раздела 2 требует `не ... , а ...` и инвертированный порядок не покрывает **в принципе**. Прецедент: греп нашёл 1 совпадение и показал «норма соблюдена», а anti-AI субагент нашёл **ещё 6** инверсий: «советует считать источником правды команду поиска, **а не описание**», «это моя рекомендация, **а не цитата** из репозитория».

```bash
# Инверсия - считать ВМЕСТЕ с прямым порядком, суммарно ≤ 1 за документ:
grep -c ', а не ' <path>
```

**Замена:** переписать утверждением. «а не описание» → «описание отстаёт». «а не цитата из репозитория» → «В репозитории такой команды нет, это моя рекомендация».

### 2.0b. «Разграничительные» темы дают лавину антитез - закладывать длинный проход

Тема, устроенная как разграничение («что помогает, а что нет», «в чём разница»), структурно рождает антитезы пачками. Прецедент: первый черновик разграничительной статьи дал **28 симметрий** (17 прямых + 11 инверсий) при норме 1; чистка заняла больше времени, чем написание.

**Правило:** для разграничительных тем сразу писать каждое разграничение как **два отдельных утверждения через точку**: «Наказывают за X. Сам Y - не состав нарушения». Грепы раздела 2 гонять **после каждой волны правок**.

**И вторая ловушка того же прецедента:** когда чинишь антитезы, **замена-затычка сама становится метрономом**. Механическая замена восьми «а не X» на «X ни при чём» дала 4 подряд - тот же выровненный ритм другими словами. **Как чинить:** (1) считать частоту и самой заменяющей фразы (`grep -c`), держать её ≤2; (2) варьировать замены между собой; (3) часть выводов-клинчеров просто удалять - читатель уже понял мысль, мораль в конце абзаца не нужна.

### 2.0c. Зеркало «ты не X, ты Y» через запятую

Ещё один разворот, который грепы выше не ловят: антитеза через личное «ты» и запятую. Считать вместе с прямыми симметриями - суммарно ≤ 1 за документ. Пример из эксплуатации: «ты не докручиваешь формулировку промпта, ты меняешь правила» - переписано утверждением: «ты управляешь правилами ещё до запроса; формулировка промпта на этом фоне вторична».

```bash
grep -nP 'ты не [^.,]{1,40}, ты ' <path>
```

### 2.0d. Смысловые вариации антитезы - грепы не ловят вообще

Даже после чистки всех «не А, а Б» остаётся семейство **смысловых** антитез со структурой «ложный вариант → отрицание → правильное», но без слова «не» и союза «а». Только семантический проход:

- **«X вместо Y»**: «скиллы вместо инструкций»;
- **«казалось X, на деле Y»**: «Логика кажется железной... на деле выходит наоборот»;
- **«не всё... только»**: «сохраняет не всё подряд, только то, что...»;
- **«X→Y»-переход в финале**: «перестанет быть свалкой и станет опорой»;
- **шаблонный «именно X» на кульминации**: «Именно это - навык, который...».

**Замена - утверждением без зеркала:** «X вместо Y» → просто «X, порциями, когда нужно»; финальный «X→Y» → обрубить на первом смысле. Суммарно все антитезы (синтаксические + смысловые) ≤ 1 за документ.

| Палево (симметрия) | Живая речь (с контекстом) |
|---|---|
| «Не А, а Б» (голая антитеза) | назвать прямо, без зеркала: «Б - и вот почему: <причина>» |
| «Не теория, а практика» | «Разбор построен на реальном примере, который можно повторить» |
| «Не инструмент, а система» | «Эта штука работает как система: <что именно она делает за читателя>» |

### 2.1. «Это не X. Это Y» через ТОЧКУ - запрещено намертво

**Что палит:** тот же разворот, что «не X, а Y», но разбитый на два предложения через точку - чтобы обойти греп выше. Формально без союза «а», по сути та же мёртвая антитеза. Самый коварный подвид - «бытовое отрицание → умный термин». Живые люди так НЕ говорят - это чистый отпечаток машины. В отличие от раздела 2 (где 1 раз можно) - здесь правило **НОЛЬ раз**.

❌ «Это не наглость. Это <умный термин>»
❌ «Это не лень. Это <научное объяснение>»
❌ «Это не магия. Это механика»
❌ «Дело не в инструменте. Дело в тебе»

✅ Живые альтернативы:
- Назвать прямо: «Это называется <термин>».
- Сразу к сути: «Так это и работает».
- Утверждением без зеркала: «И чем меньше знаешь, тем громче споришь».

```bash
# Ищет «Это не ___. Это ___» / «это не X, это Y» / «это не X - это Y» (точка/запятая/тире), регистронезависимо:
grep -niP '(это|дело)\s+не\s+[^.,;:!?]{1,45}[.,—-]\s*(это|дело)\s' <path>
```

⚠️ **Этот паттерн нельзя ловить только грепом - обязателен семантический проход** (anti-AI агент на Этапе 7). Причина: разрыв через произвольный текст (>45 символов до второго «это») греп не покрывает в принципе. Прецедент из эксплуатации: строчные варианты в середине предложения («безопасность - это не про X. Это про Y», «Это не страшилки - это публичные разборы») прошли автоматический греп, но их поймал anti-AI субагент семантически. Вывод: греп сделан `-i` + широкое окно, но финальный детектор - человекоподобный субагент.

## 3. Одиночные слова через точку

**Что палит:** «Просто. Понятно. Эффективно.» Драматургический приём «удар-удар-удар».

**Правило:** допустимо 1 раз в первом абзаце-обещании. В теле статьи - **запрещено**.

```bash
grep -nP '^\s*[А-ЯЁA-Z][а-яёa-z]{2,15}\.\s+[А-ЯЁA-Z][а-яёa-z]{2,15}\.\s+[А-ЯЁA-Z][а-яёa-z]{2,15}\.\s*$' <path>
```

| Палево | Живая речь |
|---|---|
| Просто. Понятно. Эффективно. | Один запрос, одна команда, готовый результат - за пару минут. |
| Презентации. Письма. Тексты. Продажи. | За вечер собираю всю обвязку: презентацию, рассылку, посты. |
| Быстро. Дёшево. Качественно. | Дёшево и быстро - но не за счёт качества, потому что <причина>. |

## 4. Литературные обороты (сценарные крючки)

**Что палит:** «Эпоха X закончилась», «В мире, где...», «Настоящая революция», «Эра ушла», «Настала эра», «Грядёт время», «Мы стоим на пороге», «Новая грамотность», а также усилители без содержания: «фундаментально», «кардинально», «радикально», «по-настоящему», «истина».

```bash
grep -niE '(эпох[аиыу] \S+ закончи[лас][ьья]?|в мире, где|настоящая революция|эра ушла|настала эра|грядёт время|мы стоим на пороге|новая грамотность|фундаментально|кардинально|радикально|по-настоящему|истина)' <path>
```

**Замена:** конкретный случай или личная история вместо пафосного сценария.

| Палево | Живая речь |
|---|---|
| Эпоха X закончилась. Настала эра Y. | Раньше я бы решал это так-то. Сейчас делаю иначе - за вечер. |
| В мире, где всё меняется, надо адаптироваться. | За последние месяцы я заменил три ручных процесса на один автоматический. |
| Новая грамотность - это <термин>. | <Термин> = <что конкретно читатель кладёт на вход, то и получает на выход>. Без структуры - мусор на выходе. |

## 5. Канцелярит и связки сочинения

**Что палит:** «Однако», «Таким образом», «Важно отметить», «Стоит сказать», «Следует понимать», «Необходимо учитывать», «Как было сказано выше», «Вышеупомянутый», «Также стоит отметить», «При этом важно», «Более того», «Кроме того», «является», «представляет собой», «играет ключевую роль», «обеспечивает возможность», «в заключение», «подведём итог».

```bash
grep -niE '(однако|таким образом|важно отметить|стоит сказать|следует понимать|необходимо учитывать|как было сказано выше|вышеупомянут|также стоит|при этом важно|более того|кроме того|является|представляет собой|играет ключевую роль|обеспечивает возможность|в заключение|подведём итог)' <path>
```

**Замена:** прямая речь без связок. Если без связки фраза разваливается - переписать абзац.

| Палево | Живая речь |
|---|---|
| Однако важно отметить, что таким образом мы получаем стабильный результат. | И вот тут получается стабильный результат. |
| Стоит сказать, что необходимо учитывать контекст. | Контекст решает всё. |
| Как было сказано выше, это фундаментально меняет подход. | Это меняет подход. |

## 6. Подзаголовки-крючки внутри абзацев

**Что палит:** «И самое мощное», «Главное», «Вот в чём суть:», «А теперь представь», «И тут начинается интересное», «Самое интересное», «Самое важное», «Главное запомнить».

Это машинная эвристика удерживать внимание абзацем. Живой человек не пишет так в середине текста.

```bash
grep -niE '(и самое (мощное|интересное|важное)|^главное[.:]?\s|вот в чём суть|а теперь представь|и тут начинается интересное|самое интересное|самое важное|главное запомнить)' <path>
```

**Замена:** прямо начать с сути, без «подзаголовка-вступления».

### 6.1. Авторские крючки-двоеточия «анонс важности: мысль»

Греп раздела 6 ищет фиксированный список фраз и **не берёт авторские формулировки той же конструкции**: `<анонс важности> + двоеточие + <мысль>`. Прецедент из эксплуатации: греп дал 0 попаданий, anti-AI субагент нашёл **15 крючков**, ни одного из словаря:

❌ «И вот тут важная деталь, которую путают чаще всего: ...»
❌ «Ключевой момент, который экономит нервы: ...»
❌ «Хорошая новость: ...»
❌ «Полезная мелочь: ...»
❌ «Отдельно держи в голове: ...»

Пятнадцать одинаковых конструкций подряд дают ровный метроном: каждый абзац собран по одному шаблону, и при чтении вслух это слышно сразу.

**Правило:** не более **2-3 таких крючков** на весь документ, и только живые авторские («И оговорка от себя»). Остальные - срезать до сути: «И вот тут важная деталь, которую путают чаще всего: недельное окно не скользящее» → «Недельное окно при этом не скользящее».

**Детектор для агента (греп не поможет):** пройди по документу и найди все предложения, где перед двоеточием стоит оценка важности, а не факт. Считай их. Больше трёх - режь.

### 6.2. Суперлатив-анонс перед фактом и перед цитатой

Тот же дефект, что 6.1, но без двоеточия: предложение открывается оценкой значимости, а факт приезжает следом. Прецедент: после чистки крючков-двоеточий субагент нашёл ещё **14 суперлатив-анонсов**, каждый второй абзац открывался оценкой:

❌ «**Самое неприятное для предпринимателя** нашёл исследователь…»
❌ «**Практичнее всего звучит** формулировка британского регулятора.»
❌ «**Дальше начинается техническая ловушка.**»
❌ «И одно правило на будущее, **которое стоит дороже всей этой инструкции**: …»

Отдельная подлость последнего: самооценка в финале попутно обесценивает всё, что было выше.

**Правило:** факт сам решает, насколько он важен. Убираешь анонс - смысл не теряется, ритм оживает. «Самый неудобный факт для компании X в том, что...» → «Предыдущий эпизод был у компании X же, десятью месяцами раньше».

**Детектор (греп не поможет):** найди все предложения, начинающиеся с превосходной степени («самый», «лучше всего», «практичнее всего», «главный», «ключевой») или с анонса вывода («означает одно», «что это значит», «дальше начинается»). Больше двух-трёх на документ - режь. Не автоматизируется - только семантический проход anti-AI агента.

### 6.3. Такт «подводка к цитате → цитата → обруб»

Дефект не в отдельной фразе, а в **повторе конструкции**. Текст с большим числом цитат легко собирается по одному такту: анонс важности → цитата → короткий афористичный обруб. Отдельно каждое звено нормальное, двадцать восемь раз подряд - метроном. Прецедент: черновик прошёл ВСЕ механические проверки (0 тире, 0 симметрий, 0 канцелярита), а семантический агент поставил 58/100 и нашёл 50 нарушений, включая 17 суперлатив-анонсов и ~28 абзацев из ~50 с выровненным коротким финалом.

**Что проверять (грепом не берётся):**

1. Пройти по всем цитатам и посмотреть, что стоит **перед** каждой. Больше 2-3 подводок с оценкой значимости - резать.
2. Посмотреть, чем заканчиваются абзацы подряд. Если абзац за абзацем закрывается короткой чеканной фразой - вживить часть таких финалов внутрь предыдущего предложения.

**Косвенный автоматический сигнал.** Burstiness (`scripts/ai-cadence-check.py`, коэффициент вариации длин предложений) - единственная механическая проверка, которая этот дефект нащупывает. **CV ниже 0.55 при полностью чистых грепах почти всегда означает именно выровненный ритм.**

### 6.4. Метроном мерить числом - и правки его сначала ухудшают

Слой burstiness ловит разброс длин предложений, но **не видит позицию финала**. Текст может иметь отличный CV и при этом закрывать чеканной фразой каждый второй абзац. Замер - отдельным счётом: доля абзацев, чьё последнее предложение короче 75 символов. **Цель - ниже 35%.**

Прецедент: первый черновик 53% → после волны правок по находкам агента **56%** (каждая правка рубила фразу короче) → после целенаправленного сращивания финалов 22%. Поэтому: мерить до правок, мерить после правок, и вживление финалов делать **отдельным проходом**, а не заодно.

| Палево | Живая речь |
|---|---|
| И самое мощное: <фича> работает без интернета. | <Фича> работает без интернета. |
| А теперь представь: ты делаешь одно действие. | Одно действие - и дальше всё происходит само. |

## 9. Мотивационная симметрия и инфоцыганские маркеры

⚠️ «Гарантирую результат» и подобные обещания - не только AI-маркер, но и юридический риск (см. `references/checklists/compliance.md`: гарантированный результат в продающем тексте - повод для претензии регулятора по рекламе в большинстве юрисдикций). Держи эти обороты в `editorial.banned_words`.

```bash
grep -niE '(у тебя получится|верю в тебя|это меняет всё|кто понял|осталось [0-9]+ мест|цена вырастет|успей пока не|секрет миллион|гарантиру[еюя]|дорогие друзья|солнышки|мои дорогие)' <path>
```

## 10. Стартовые и закрывающие шаблоны

**Запрещены в начале:** «Привет, друзья!», «Сегодня поговорим о…», «В этой статье вы узнаете…», «Здравствуйте, дорогие», «Сегодня я хочу поделиться».

**Запрещены в конце:** «Спасибо за внимание», «Подписывайтесь на канал» (как самостоятельный CTA без выгоды), «Жду вас в комментариях», «До новых встреч».

**Что вместо:**
- В начале - сразу с сути (первое предложение = главный инсайт).
- В конце - конкретное следующее действие (CTA с UTM на `cta.offer`).

```bash

grep -niE '(спасибо за внимание|подписывайтесь на канал|жду вас в комментариях|до новых встреч)' <path>
```

## 11. Ритмика трёх коротких подряд (burstiness)

**Что палит:** три коротких предложения подряд одинаковой длины (особенно в финале) - машинный «удар-удар-удар». Языковые модели выравнивают длину предложений, человек пишет рвано.

**Правило:** живая речь дышит - длинное предложение, короткий обрыв, ещё длинное. Перепад длины обязателен.

**Метрика (если есть инструмент).** Коэффициент вариации длин предложений `CV = stdev(длины) / mean(длины)`:
- `CV ≥ 0.55` - живой рваный ритм. ✅
- `0.40 ≤ CV < 0.55` - средний, типично для технотекстов. ⚠️
- `CV < 0.40` - слишком ровно, машинный маркер.

Без инструмента - ручная проверка чтением вслух (Шаг 8.7).

## 12. Кальки с английского машинного стиля

**Что палит:** прямые кальки оборотов, которыми языковые модели набиты на англоязычных корпусах: `delve`, `moreover`, `furthermore`, `leverage`, `robust`, `comprehensive`, `tapestry`, `landscape`, `journey`, `realm`, а в переводе на русский - «погружаемся в», «в постоянно меняющемся ландшафте», «бесшовно», «надёжное решение», «всеобъемлющий».

```bash
grep -niE '(delve|moreover|furthermore|leverage|robust|comprehensive|tapestry|landscape|journey|realm|погружаемся в|меняющемся ландшафте|бесшовн|всеобъемлющ)' <path>
```

**Замена:** прямое русское слово, простой глагол.

## 13. Бренд и авторские термины

**Что палит:** искажение написания вашего бренда/продукта (склонение, регистр, замена букв). Конкретные канонические формы и частые ошибки берутся из `config.*` (поле бренд-написания) и `editorial.banned_words`.

```bash
# Соберите регэксп ошибочных написаний бренда из config.* / editorial.banned_words:
grep -nE '<ошибочное-написание-1>|<ошибочное-написание-2>' <path>
```

**Авторские термины** из вашего `voice.source` (характерные метафоры, частотные слова, сильные обороты автора) - использовать как есть, не подменять синонимами. Терминология должна быть авторская, не выглаженная машиной.

## 14. Стоп-словарь ниши (`editorial.banned_words`)

Всё нишевое и юридически чувствительное - в `editorial.banned_words` (бренд-табу, лицензируемые термины вашей ниши, нежелательные формулировки). Полную механику проверки и разбор юр-категорий см. `references/checklists/compliance.md`. Здесь - анти-AI оптика: эти слова часто всплывают именно из машинной генерации, потому что модель тянет «стандартную» лексику ниши, не зная ваших ограничений.

```bash
# Соберите регэксп из editorial.banned_words (корни/фразы через |):
grep -niE "<корень-1>|<корень-2>|<фраза-3>" <path>
```

Особый случай: слово из стоп-словаря, процитированное как пример самого правила (самоописание), - не нарушение, помечайте отдельно. Имена собственные (сторонний продукт может легально содержать корень из списка) - тоже исключение.

## 15. Англицизмы с русским аналогом (`editorial.banned_words`)

Если ваша ниша требует чистого языка (или этого требует регулятор в вашей юрисдикции) - держите англицизмы с готовым русским аналогом в `editorial.banned_words`. Это и читаемость, и в ряде юрисдикций - требование по языку рекламы (см. `references/checklists/compliance.md`).

| Не говорим (пример) | Говорим |
|---|---|
| оффер | предложение |
| лиды, лид-форма | заявки, форма заявок |
| контент | материалы, тексты, содержимое |
| кастомный | индивидуальный, свой |
| дефолтный | стандартный, по умолчанию |
| фидбэк | обратная связь |

> Конкретный словарь «не говорим / говорим» - ваш, в `editorial.banned_words`. Таблица выше - пример формата.

⚠️ **Не гонять автозамену англицизмов вслепую.** Сначала проверить каждое вхождение: «это термин или имя собственное?» Имя продукта/канала - не англицизм и не перевод. Прецедент из эксплуатации: глобальный авто-replace латиницы превратил имя стороннего продукта и название чужого канала в исковерканный кириллический мусор. Имена собственные из `voice.forbidden`/`config.*` исключать из замены.

## 16. Аудитория и тон (`audience.profile` + `voice.source`)

**Не пихать лишние внутренности.** Если читатель из `audience.profile` не специалист - не вываливать технический стек/жаргон, показывать **результат** «что эта штука делает за меня», а не как она устроена. Жаргон даём по `audience.jargon_level`: `low` - объясняем термины, `high` - можно экспертно.

| Палево (стек-фокус) | Живая речь (результат-фокус) |
|---|---|
| «Используем <технология> с <деталь> для оптимизации» | «Эта штука находит нужное за доли секунды даже на больших объёмах» |
| «<Библиотека> даёт типизированные миграции» | «Когда я меняю структуру, всё пересобирается само» |

**Обязательно для тона** (эталон - тексты из `voice.source`):
- **Прямая речь от первого лица:** «я делаю», «у меня работает», «я бы взял» - не «рекомендуется», «принято считать».
- **Конкретные кейсы и реальные цифры** вместо абстракций (цифры - проверенные, см. факт-чек).
- **Авторские термины** автора, из `voice.source`.
- **Единое обращение к читателю** (на «ты» ИЛИ на «вы» по `audience.profile`, без срывов).
- **Без мотивационного слоя** («у тебя получится», «верю в тебя», «это меняет всё»).
- **Без давления и инфоцыганщины** («осталось N мест», «гарантирую результат»).
- **Ни одной фразы из `voice.forbidden`.**

## Полный цикл хуманизации (Этап 8)

1. **Автоматический чек** - прогнать `scripts/ai-cadence-check.py` (AI-маркеры: типографика, симметрии, обороты, канцелярит) и `scripts/structure-check.py` (структура: один H1, непустые H2, источники, основной CTA, alt у картинок, минимум внутренних ссылок). Стоп-слова из `editorial.banned_words` - ручным grep. TL;DR в каждом H2 и атрибуцию цитат - глазами. Результат - baseline нарушений в `work/<slug>/`.
2. **Безопасные автозамены** (раздел 1) - где замена детерминирована:
   ```bash
   sed -i '' 's/—/-/g; s/–/-/g; s/…/.../g' <path>
   ```
   Англицизмы и латиницу - **не вслепую** (раздел 15), имена собственные исключать.
3. **Multi-agent QA** (Этап 7) - 6 параллельных субагентов в свежем контексте: anti-AI (разделы 1-12, особенно не-автоматизируемые: симметрии, крючки, безличные, шаблонные финалы), стоп-слова/compliance (`editorial.banned_words`), тон/голос (`voice.source` + `voice.forbidden`), факт-чек (каждая цитата/цифра на первоисточнике), SEO-структура, перелинковка.
4. **Применение находок** - точечные `Edit` по приоритетам (🔴 критично → 🟡 важно → 🟢 желательно).
5. **Повторный прогон** `scripts/ai-cadence-check.py` и `scripts/structure-check.py`. Целевой результат - **0 fails** в обязательных проверках.
6. **Ручной grep** (Шаг 8.6) по неавтоматизируемым паттернам (разделы 2, 6, 7, 8, 9) + по каждому слову из `editorial.banned_words` и `voice.forbidden`. Каждое попадание - исправить или **явно** подтвердить «допустимо в этом контексте» (например, ровно одна симметрия во вступлении). «По умолчанию допустимо» - не вариант.
7. **Чтение вслух** (Шаг 8.7) ключевых участков (H1, первый абзац, заголовки H2, TL;DR, финал). Спотыкаешься или звучит «не как живой человек из `audience.profile`» - переписать строку. Эталон - ритм текстов из `voice.source`.
8. **Если всплыл новый антипаттерн** - занести сюда (Rule → Why → How) + опционально правило в `scripts/ai-cadence-check.py`. Следующая статья ловит автоматически.

**Gate перед Этапом 9:** `scripts/ai-cadence-check.py` и `scripts/structure-check.py` = 0 fails **и** ручной grep = 0 (или остаток явно подтверждён) **и** чтение вслух пройдено.
