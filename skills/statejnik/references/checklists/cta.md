# Чек-лист CTA-архитектуры статьи

> **Когда читать:** перед написанием черновика (Этап 6). Этот файл фиксирует **где, в какой формулировке и с какой связкой** ставятся призывы к действию (CTA), чтобы конверсия в подписку/оффер была максимальной, без перегрузки читателя.
>
> **Главный принцип:** **3 обязательные точки CTA** в каждой статье + 1-3 опциональные блока удержания. Не больше, не меньше - иначе читатель перегружен и игнорирует. Этот файл - единая точка истины конверсионной структуры.
>
> **Источник данных:** все три точки тянут текст и ссылку оффера из `statejnik.yaml` (`cta.offer`, `cta.url`) и параметры подписного канала из `config.*`. Не вписывай ссылку, цену и условия руками в нескольких местах - поменяешь оффер один раз в конфиге, и он обновится во всех статьях. Числовые параметры оффера (цена, даты, длительность) рендерит родовой блок оффера из вашей системы, чтобы они нигде не разъехались.

## Карта 3 точек CTA

```
┌─────────────────────────────────────────────────────────┐
│  H1                                                      │
│  Обещание читателю (что узнает + применит за + сложность)│
│                                                          │
│  ⭐ ТОЧКА 1 - подписка / первый контакт (above-the-fold) │
│                                                          │
│  ## H2 #1                                                │
│  TL;DR ...                                               │
│  ## H2 #2                                                │
│  TL;DR ...                                               │
│                                                          │
│  ⭐ ТОЧКА 2 - встроенный оффер (~25-35% длины)          │
│                                                          │
│  ## H2 #3-N - основная часть                            │
│  (опц.) блок удержания на ~p50                           │
│                                                          │
│  ## Заключительный H2 (что дальше)                       │

│                                                          │
│  ⭐ ТОЧКА 3 - подвал (автор + оффер крупно)             │
│                                                          │
│  (опц.) sticky-баннер - поверх всего, dismissable        │
└─────────────────────────────────────────────────────────┘
```

## ⭐ ТОЧКА 1 - подписка / первый контакт (above-the-fold)

**Позиция:** сразу после блока-обещания читателю, до первого H2.

**Зачем:** читатель только что увидел обещание статьи («что узнаешь», «применить за», «сложность»). Это пиковый момент интереса - не перебивая чтение, дать **самый лёгкий следующий шаг**: подписка на ваш канал обратной связи (рассылка, сообщество, мессенджер - что объявлено в `config.*`), бесплатно, в один клик. Кто подписался - попадает в вашу лояльную аудиторию надолго.

**Формулировка** - короткая проза-связка + родовой блок подписки:

```
Каждую неделю разбираю новое по теме <ВАША_НИША>: инструменты, примеры, ошибки.
Подпишись, чтобы быть в курсе.

[блок подписки - рендерится из config.*]
```

Смысл связки - «оставайся на связи, чтобы быть в курсе по теме», а не агрессивная продажа в первом экране.

**UTM-метки (auto через сам блок):**
- `utm_source=<статья>`
- `utm_medium=cta`
- `utm_campaign=<slug>`
- `utm_content=<тип-канала>`

**Запреты:**
- ❌ Не дублировать блок подписки больше одного раза за статью.
- ❌ Не дублировать подписку в sticky-баннере - читатель обозлится.
- ❌ Не вставлять QR-код / тяжёлую картинку above-the-fold - это перегруз первого экрана.
- ❌ Если читатель пришёл по UTM вашего же канала (он уже подписчик) - не предлагать «Подпишись» тем же текстом (детект `utm_source` - опциональная подмена, держите в backlog).

## ⭐ ТОЧКА 2 - встроенный оффер (~25-35% длины)

**Позиция:** после первых 2-3 H2 (читатель погрузился в материал, оценил пользу). Примерно на скролл-глубине 25-35%. Считай: сколько разделов до первого оффер-блока - должно быть 2-3.

**Зачем:** «открыл аппетит» - читатель видит, что одна статья решает один вопрос, и теперь предлагаем «полную картину» (`cta.offer`). Самый горячий момент для конверсии.

**Формулировка** - родовой блок оффера (вариант «встроенный»), который сам подтягивает заголовок, параметры и кнопку из `config.*` / вашей системы. Перед блоком - проза-связка темы статьи с оффером.

### Конструктор связки (3 строки)

1. **К какой части вашего оффера относится тема статьи.**
2. **«<тема> - это <роль темы в вашем оффере>»** (одна фраза, показывает, что статья - кусочек большего).
3. **Мост к офферу:** «<ВАШ_ОФФЕР> даёт полную картину / полную связку» (1-2 фразы, без давления).

```
Хочешь собрать систему целиком? То, что в статье, - лишь первый шаг.
<ВАШ_ОФФЕР> ставит все шаги вместе и доводит до результата.

[блок оффера, вариант «встроенный» - рендерится из config.*]
```

> ⚠️ **Не переписывай дефолты блока «просто чтобы что-то поменять».** Карточка оффера единая по проекту (Точка 1, статьи, sticky-баннер) - чтобы у читателя складывался узнаваемый образ. Меняй заголовок/подзаголовок блока, только если тема статьи требует другого фрейма.

### Запреты для Точки 2

- ❌ **Не использовать давящие формулировки:** «гарантирую результат», «осталось N мест», «только сегодня», «успей до». Это и манипуляция, и юр-риск (обещание результата + ложная срочность - см. `references/checklists/compliance.md`). Все табуированные обороты держи в `editorial.banned_words` - на Этапе 8 стоп-словарь их ловит.
- ❌ Не толкать **самый дорогой** оффер холодному читателю в Точке 2. В начало - мягкий вход (подписка, недорогой первый шаг). Дорогой оффер - только тёплой аудитории ниже по тексту или в подвале.
- ❌ Не лепить встроенный оффер на p10% (читатель ещё не разогрелся) или на p70-80% (там Точка 3 + sticky-баннер).
- ❌ Не вписывать цену и даты руками рядом с блоком - он показывает их сам из `config.*`. Хочешь напомнить параметры прозой - только в одном месте.
- ❌ Встроенный оффер - не более двух раз за статью.

## ⭐ ТОЧКА 3 - подвал (автор + оффер крупно)

**Позиция:** в самом низу, после заключительного H2 («что дальше»), рядом с блоком «Источники».

**Зачем:** читатель прошёл всю статью → высокая глубина → готов к **большему обязательству**. Здесь крупный блок с 3 элементами в одном:

1. **Bio автора** (фото + имя + должность + 1-2 предложения).
2. **Публичные каналы** автора (из `config.*` / профиля автора).
3. **Крупный блок оффера** (`cta.offer`).

### Если CMS вставляет подвальный CTA автоматически

Если адаптер площадки (publish.py) умеет рендерить подвальный блок оффера + карточку автора сам после тела статьи - **не дублируй их в черновике.** Поставь только короткий проз-«мостик» в 1-2 предложения после блока «Источники», а крупный блок отрендерит адаптер:

```
> Источники
> - ...

Полная картина по теме <ВАША_НИША> - за один заход. <ВАШ_ОФФЕР>: коротко, по делу,
с результатом, который остаётся у тебя.

[крупный блок оффера в подвале + карточка автора - вставляет адаптер площадки, в черновик не пишем]
```

> ⚠️ **Запрет:** не вставляй родовой блок оффера (вариант «подвал») и карточку автора в тело вручную, если их вставляет адаптер. Дубликат карточки = раздражение читателя.

### Если CMS не умеет авто-подвал

Если площадка `manual` или простой `custom` - поставь блок оффера + карточку автора в черновик руками **один раз**, в самом конце.

### Запреты для Точки 3

- ❌ Не использовать новые каналы кроме тех, что уже в профиле автора (`config.*`).
- ❌ Не дублировать подписку из Точки 1 без вариации текста. Читатель видит «Подпишись» уже дважды - это раздражает; в Точке 3 - другая семантика («автор ведёт канал по теме»).

## Опциональные блоки удержания (между Точками 2 и 3)

### Блок-крючок на ~p50 (для длинных статей)

**Зачем:** удержать внимание между Точкой 2 (~30%) и Точкой 3 (подвал). Не CTA как таковой - картинка, цитата, дополнительный пример, который **не выбрасывает читателя со страницы**, а возвращает в чтение.

**Когда:** длинные статьи (опорные, 6К+ слов). Для инструкций/разборов 3-5К слов обычно достаточно 1 крючка на p50.

### Sticky-баннер - закреплённый внизу экрана

**Зачем:** мягкий «всегда видимый» CTA. Меняется по скролл-глубине:
- p0-50% - «Читай дальше», не настойчиво.
- p50-80% - «Подпишись», мягко.
- p80-100% - оффер, сильно.

**Поведение:** dismissable (X в углу), запоминается на ~7 дней.

**Запрет:** не показывать sticky-баннер одновременно с Точкой 3 в видимой области (избегать дублирования) - скрывать баннер, когда подвал в зоне видимости.

## Pre-publish gate (для SEO/структурного агента в Этапе 7 + Этап 13)

- [ ] **Точка 1** - блок подписки above-the-fold (после обещания, до 1-го H2). Перед блоком - короткая проза-связка. Считай: блок подписки не повторяется >1 раза.
- [ ] **Точка 2** - встроенный оффер на 25-35% контента. Перед блоком - проза, связывающая тему статьи с оффером. До первого оффер-блока - 2-3 раздела. Встроенный оффер не повторяется >2 раз.
- [ ] **Точка 3** - подвальный оффер + карточка автора. Если CMS вставляет авто - в теле только проза-«мостик» 1-2 предложения, сам блок не дублировать (flag «удалить, рендерится автоматически»). Если не вставляет - блок в черновике один раз в конце.
- [ ] Опционально: блок-крючок, если длина >6K слов (вручную в середине).
- [ ] Опционально: sticky-баннер встроен на уровне шаблона страницы (не в теле статьи).
- [ ] UTM-метки автоматические через сами блоки (не дублировать руками). Целевой URL = `cta.url`, живой.
- [ ] Нет дублей: блок подписки ≤1 раза, встроенный оффер ≤2 раз.
- [ ] Все формулировки прошли через `references/checklists/anti-ai.md` (нет «гарантирую», «осталось N мест», «успей»).
- [ ] Все формулировки прошли через `references/checklists/compliance.md` (нет обещаний гарантированного результата и ложной срочности).
