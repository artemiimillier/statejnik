# Независимые роли: как запускать в любом агенте

Процесс требует четыре независимые роли: выбор темы, проверяющий статьи, финальный редактор, сверяющий финал. Независимость значит: свежий контекст без истории автора, на входе только файлы. Имитировать роль в своём контексте («представь, что ты другой агент») нельзя.

## Способ запуска - по порядку предпочтения

1. **Встроенный субагент агента.**
   - Hermes: инструмент `delegate_task` - в задачу передать текст промпта целиком (или «прочитай промпт из файла `<путь>` и выполни»).
   - Claude Code: инструмент Task (субагент) с тем же промптом.
   - Другие агенты - их аналог «запустить подзадачу в чистом контексте».
2. **Отдельный неинтерактивный процесс**, если встроенного субагента нет. Промпт собрать скриптом в файл (`prompt.py`, ниже) и передать процессу. Процесс должен работать **в рабочей папке проекта** - иначе он не найдёт `work/` и выдаст «файл не найден» или пустой, выдуманный вердикт.
   ```bash
   # Hermes: -z восстанавливает свою папку, поэтому рабочую папку указывать явно через --in
   hermes --in "$PWD" -z "$(cat work/<slug>/_prompts/review-1.md)" > work/<slug>/review-1.md
   # то же без подстановки в командную строку (длинный промпт, кавычки в тексте):
   hermes chat --in "$PWD" --query-file work/<slug>/_prompts/review-1.md -Q > work/<slug>/review-1.md

   # Claude Code: запускать из рабочей папки (cd в неё); доступ к файлам вне неё - через --add-dir
   claude -p "$(cat work/<slug>/_prompts/review-1.md)" --add-dir "$SKILL_DIR" > work/<slug>/review-1.md

   # Codex: из рабочей папки
   codex exec "$(cat work/<slug>/_prompts/review-1.md)" > work/<slug>/review-1.md
   ```
   Проверить, что процесс видит файлы, можно коротким вопросом до долгого запуска: `hermes --in "$PWD" -z "Прочитай work/plan.md и ответь первой строкой файла"`. Инструменты веба и чтения файлов процессу нужны (проверяющий переоткрывает источники); если CLI спрашивает разрешения на каждую команду, в неинтерактивном режиме он встанет - смотрите `--help` своего CLI (у Claude Code - `--allowedTools` / `--permission-mode`, у Hermes - `-t` для набора инструментов).

   **Время.** Один вызов проверяющего - 5-15 минут (больше источников - дольше). Запускать в фоне, вывод - в файл, код выхода - рядом (`; echo $? > work/<slug>/review-1.exit`), и ждать завершения: если у агента ограничено время одной команды (например, 180 или 600 с), повторять ожидание, а не убивать процесс и не запускать второй. Пустой файл ответа или ненулевой код - сбой, не accept.
3. **Ни то, ни другое недоступно** - остановиться и сообщить владельцу. Ручное «принято» автором не допускается.

## Готовые промпты

| Роль | Шаблон | Куда ответ |
|---|---|---|
| Выбор темы (автопилот, серия; одна статья без темы от владельца) | `templates/prompts/select.md` | `work/<slug>/selection-raw.md` → `selection.md` |
| Независимый проверяющий | `templates/prompts/review.md` | `work/<slug>/review-<N>.md`, последний - `review.md` |
| Финальный редактор | `templates/prompts/final-editor.md` | `final-review/iteration-<M>/candidate.md`, `editor.md` |
| Сверяющий финал | `templates/prompts/final-verify.md` | `final-review/iteration-<M>/verdict.md` |

Промпт собирает скрипт - руками шаблон не правят:

```bash
python3 $SKILL_DIR/scripts/prompt.py review       --slug <slug> --round <N> > work/<slug>/_prompts/review-<N>.md
python3 $SKILL_DIR/scripts/prompt.py final-editor --slug <slug> --round <M> > work/<slug>/_prompts/final-editor-<M>.md
python3 $SKILL_DIR/scripts/prompt.py final-verify --slug <slug> --round <M> > work/<slug>/_prompts/final-verify-<M>.md
python3 $SKILL_DIR/scripts/prompt.py select       --slug <папка>             > work/<папка>/_prompts/select-1.md
```

В шаблонах единые плейсхолдеры `{{WORKDIR}}`, `{{SLUG}}`, `{{ROUND}}`, `{{PREV_ROUND}}`, `{{SKILL_DIR}}`, `{{CONFIG}}`; блок повторного круга `{{#REPEAT}} ... {{/REPEAT}}` скрипт оставляет только на кругах 2-3. Фрагмент `statejnik.yaml` (project, audience, voice, cta, editorial) вклеивается в промпт; остальные материалы передаются **путями**, субагент читает их сам - так промпт короткий, а материалы полные. Скрипт предупреждает, если чего-то не хватает (нет `checks/<N>/summary.md` - не прогнан `check-all.py`; нет `fixes-<N-1>.md` или `diff.txt` на повторном круге). В промпт сверяющего финал разбор редактора (`editor.md`) не попадает - скрипт это проверяет. Сохранённый промпт - часть доказательств.

## Что передавать на повторном круге проверки

- новую версию (`draft.md`) и актуальные `claims.json`, `sources/`;
- прошлый вердикт целиком (`review-<N-1>.md`);
- `work/<slug>/fixes-<N-1>.md` - список исправлений автора по пунктам: «блокер 2 - фраза заменена на ..., запись C7 сужена». Без оправданий и споров;
- diff с прошлой версией (`diff -u` старой и новой копии в `checks/<N>/diff.txt`);
- свежий вывод проверок (`check-all.py --round <N>` после последней правки).

Прошлый вердикт и список исправлений - не история автора, а материалы: без них новый проверяющий не знает, что проверять в первую очередь. Рассуждения автора, переписку и объяснения «почему я так написал» не передавать.

## Изоляция от ключей

Ключи лежат в `.env` рабочей папки, а не в промпте. В каждом шаблоне есть запрет читать `.env` и публиковать. Субагенту не давать инструменты публикации (MCP площадок, `publish.py`). Если отдельный процесс запускается с полным набором инструментов и это нельзя сузить, для строгой изоляции собрать материалы в отдельную папку без `.env` (`work/<slug>/` + нужные справочники) и запускать процесс из неё.

## Если веб у субагента не работает

`web_extract` бывает пустым на сайтах, которые рисуют текст скриптами или закрыты антиботом. Порядок: `web_extract` → `curl` / `python3 $SKILL_DIR/scripts/fetch-source.py <url> --out ...` → браузер. Не удалось ни одним способом - сверка с сохранённой копией в `sources/` с пометкой «онлайн не переоткрыт, копия от <дата>». Для цен, наличия, сроков и лимитов старая копия не годится - такое утверждение остаётся неподтверждённым.

## Время и бюджет

Ориентиры по реальным прогонам:

- один вызов субагента - 5-15 минут (больше материалов и источников - дольше); запускать в фоне;
- полная статья по процессу: выбор + 1-3 круга проверки + 1-3 пары финальной вычитки - обычно 5-8 вызовов, 40-90 минут только ожидания, плюс работа автора.

Заранее задать пределы в `work/<slug>/status.md`: например, не больше 8 вызовов субагентов на статью. Где сокращать без потери качества:

- тему назвал владелец - вызов выбора не нужен;
- до сдачи проверяющему прогнать `check-all.py` и самому закрыть механику - иначе круг уходит на то, что ловит скрипт;
- в промпт передавать пути, а не текст; справочники - «по мере надобности», а не «прочитай все»;
- на повторном круге проверяющий начинает с прошлых блокеров и diff;
- замечания не требуют нового круга: если блокеров нет, статья принята, замечания записываются в `accepted.md`;
- финальная вычитка чаще всего проходит за одну пару, если проверяющий уже принял текст и призывы к действию не переписываются.
