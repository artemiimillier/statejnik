# Статейник - SEO-агент для Яндекса и Google

Находит, какие вопросы ищут люди в вашей нише, проверяет, на какие из них у сайта ещё нет статей, и пишет сильные статьи под эти запросы. Публикует в ваш WordPress, Blogspot, Дзен (RSS), через MCP или вебхук. Работает на любом агенте с доступом к файлам и терминалу (Hermes, Claude Code, Codex). Скриптам нужен только Python 3.9+, сторонние библиотеки не требуются.

Вся специфика проекта лежит в двух файлах рабочей папки: `statejnik.yaml` (ниша, аудитория, голос, площадки) и `.env` (ключи). Навык своих данных не содержит.

## Когда использовать

- «настрой статейник», «подключи статейник к сайту», «собери семантику», «какие статьи писать»
- «напиши статью», «следующая статья из плана», «опубликуй статью»
- Не для постов в соцсети и рассылок: там другой формат и другие правила.

## Пути

- `SKILL_DIR` - папка этого навыка (где лежит этот файл). Скрипты: `$SKILL_DIR/scripts/`.
- Рабочая папка проекта - то место, где лежат `statejnik.yaml`, `.env` и `work/`. Все команды запускать из неё (`terminal(workdir=...)`). По умолчанию `~/statejnik-<домен>`.

## Режим 1. Первая настройка (если в рабочей папке нет `statejnik.yaml`)

Вести по `references/onboarding.md` строго по шагам, по одному вопросу за раз. Кратко:

1. **Сайт.** Спросить ссылку. `python3 $SKILL_DIR/scripts/site.py scan <url> --out work/site.json`. По главной и заголовкам самому понять нишу, продукт, аудиторию, регион. Показать вывод в 3-5 строк и спросить «верно?». Готово, когда владелец подтвердил.
2. **Конкуренты.** `web_search` по 3-5 главным запросам ниши → выбрать 3-5 сайтов, которые в выдаче со статьями. Каждый прочитать `site.py scan <url> --max-pages 30 --out work/competitors/<домен>.json`. Выписать, какие темы у них есть. Готово, когда есть список конкурентов с их темами.
3. **Стартовые фразы.** Составить 10-30 маркерных фраз ниши (без брендов конкурентов), показать владельцу.
4. **Ядро.** `python3 $SKILL_DIR/scripts/keywords.py --seeds-file work/seeds.txt --expand --out work/keywords.json`. Если в `.env` есть `WORDSTAT_TOKEN`, будут частоты Вордстата. Без токена будут только подсказки Яндекса и Google (частоты нет). Как получить токен: `references/onboarding.md`. Готово, когда в файле 100+ фраз.
5. **Что уже есть на сайте.** `python3 $SKILL_DIR/scripts/site.py gap work/site.json work/keywords.json --out work/gap.json --plan work/plan.md`. Затем вручную пройти план: убрать чужие и коммерческие темы, склеить дубли, добавить темы конкурентов, которых у сайта нет. Готово, когда в `work/plan.md` 10-30 тем, каждая в отдельной строке с главным запросом.
6. **Голос и оффер.** Спросить, что продаём в статьях (ссылка на оффер), кто читатель, запреты (слова, темы, юр. ограничения). Спросить 2-3 примера текстов владельца для голоса (по желанию).
7. **Площадки.** Спросить, куда публиковать, и настроить каждую площадку по `references/publishers.md`. Для каждой обязательно выполнить `python3 $SKILL_DIR/scripts/publish.py check <имя>`. Готово, когда check проходит у всех площадок.
8. **Конфиг.** Собрать `statejnik.yaml` по `templates/statejnik.example.yaml`, ключи - в `.env` по `templates/env.example`. Показать владельцу итог: ниша, план (первые 10 тем), площадки. Предложить написать первую статью.

## Режим 2. Статья

Процесс - `references/methodology.md` (16 этапов). Коротко:

1. Взять следующую тему из `work/plan.md` (или тему владельца). Проверить, что её нет на сайте: `site.py gap` или поиск по `work/site.json`.
2. Исследование через `web_search` / `web_extract`: топ-10 выдачи по главному запросу, первоисточники, факты с ссылками. Каждое утверждение с цифрой - только с источником.
3. Структура: H2 в форме вопросов из ядра, TL;DR первым абзацем каждого раздела. Скелет - `templates/draft-skeleton.md`.
4. Текст в `work/<slug>/draft.md`. Правила - `references/editorial/editorial-standard.md`, анти-ИИ - `references/checklists/anti-ai.md`.
5. Проверки (все должны пройти):
   ```
   python3 $SKILL_DIR/scripts/structure-check.py work/<slug>/draft.md
   python3 $SKILL_DIR/scripts/ai-cadence-check.py work/<slug>/draft.md
   python3 $SKILL_DIR/scripts/read-aloud-check.py work/<slug>/draft.md
   python3 $SKILL_DIR/scripts/originality-check.py work/<slug>/draft.md work/sources/
   ```
   Плюс чек-листы `references/checklists/seo-geo.md`, `compliance.md`, для России - `legal-ru.md`. Финальная вычитка - `references/editorial/final-review.md`, лучше свежим субагентом (`delegate_task`).
6. Сохранить `work/<slug>/final.md`. Публикация черновиком: `python3 $SKILL_DIR/scripts/publish.py send <площадка> work/<slug>/final.md --status draft`. Боевая публикация (`--status publish`) - только если владелец разрешил автопубликацию (`publish.auto: true`) или сказал «публикуй».
7. После публикации на сайте: `python3 $SKILL_DIR/scripts/publish.py ping <url>` (IndexNow, если настроен), отметить тему в `work/plan.md` как сделанную, отчёт владельцу по `references/owner-report.md`.

## Режим 3. Автопилот

Если владелец хочет «N статей в день без меня»: в Hermes - `hermes cron create "0 9 * * *" "Статейник: напиши и опубликуй следующую статью из плана" --skill statejnik --workdir <рабочая папка>`. В других агентах - их планировщик или системный cron с вызовом агента в неинтерактивном режиме. Если план закончился, заново собрать ядро (шаги 4-5).

## Подводные камни

- Подсказки Яндекса и Google не дают частоту. Без токена Вордстата частоты в плане будут «-». Приоритет тогда ставится по числу подсказок и по конкурентам.
- `site.py gap` сверяет по заголовкам и адресам. Это черновой фильтр, перед тем как писать, тему всё равно проверить поиском `site:домен запрос`.
- Дзен забирает RSS сам, раз в какое-то время. Файл ленты должен лежать в папке, которую раздаёт ваш сайт, и лента один раз подключается в Студии Дзена.
- Refresh-токен Google для приложения в статусе «Testing» живёт 7 дней. Для Blogspot приложение нужно перевести в «In production».
- Не выдумывать факты, цифры, отзывы и цены. Нет источника - нет утверждения.
- Не публиковать поверх статьи с `status: blocked` во frontmatter (скрипт сам остановит).

## Проверка, что всё работает

- `python3 $SKILL_DIR/scripts/publish.py list` показывает площадки, `check` по каждой без ошибок.
- `work/keywords.json`, `work/gap.json`, `work/plan.md` существуют и не пустые.
- После статьи: `work/published.json` содержит slug и id на каждой площадке, ссылка открывается.
